Vie air-gappediin: export, siirto ja käyttöönotto

Vaiheiden ohjeet ja kopioitavat komennot ovat alla samoilla numeroilla.

1. Hae mallit Model Hubiin

Välilehti 1. Hae malli: hae malli Hugging Facesta ja lataa se kontin /models-kansioon. Toista kaikille malleille, jotka tarvitset air-gapped-päässä.

2. Vie Model Hub: aja komento kontin ulkopuolella

Kontti ei voi paketoida itseään, joten komento ajetaan isäntäkoneen terminaalissa kansiossa model_hub, ei tässä sovelluksessa. Lataukset ja kopioinnit kannattaa antaa valmistua ensin.

Bash (Linux, macOS, Git Bash, WSL):

./export.sh

Windows PowerShell:

powershell.exe -ExecutionPolicy Bypass -File ./export_with_models.ps1

Nopeampi (ei pakkausta, malliarkisto ei pakkaudu juuri): lisää loppuun --no-compress (PowerShell: -NoCompress).

2b. Jos skriptejä ei ole saatavilla

Sama käsin (kontin nimi model-hub):

docker commit --change "ENV MODEL_HUB_OFFLINE=1" model-hub model-hub:airgap
mkdir -p dist
docker save model-hub:airgap | gzip > dist/model-hub-with-models.tar.gz
cd dist && sha256sum model-hub-with-models.tar.gz > model-hub-with-models.tar.gz.sha256

3. Kopioi tikulle

  • dist/model-hub-with-models.tar.gz ja dist/model-hub-with-models.tar.gz.sha256 (pakolliset)
  • start.sh kansiosta model_hub (suositus)

Tikku: exFAT tai NTFS (FAT32 ei salli yli 4 GB:n tiedostoja). Vapaata tilaa tarvitaan vähintään arkiston koko.

Varoitus: älä poista konttia (docker rm) ennen kuin siirto on varmistettu. Se poistaa myös mallit.

Vaihe 2: air-gapped-kone

Koneella tarvitaan Docker tai Podman sekä verkkoyhteys OpenShift-klusterin API:in (oc on kontin sisällä).

4. Kopioi tikulta, tarkista ja lataa

Kopioi tikun tiedostot omaan kansioon (esim. ~/model-hub-siirto; vapaata tilaa arkiston koko kertaa kaksi). Tarkista summa ja lataa image:

cd ~/model-hub-siirto
sha256sum -c model-hub-with-models.tar.gz.sha256   # pitää tulostaa: OK
docker load -i model-hub-with-models.tar.gz        # podman load -i ...
docker images | grep model-hub                      # näyttää model-hub:airgap

Windows PowerShell: (Get-FileHash model-hub-with-models.tar.gz -Algorithm SHA256).Hash.ToLower(), vertaa .sha256-tiedostoon. Latauksen jälkeen .tar.gz voi poistaa.

5. Käynnistä Model Hub

MODEL_HUB_IMAGE=model-hub:airgap bash ./start.sh

Ilman skriptiä:

docker run -d --name model-hub --restart unless-stopped -p 127.0.0.1:8767:8767 \
  model-hub:airgap

Avaa sitten selaimessa http://127.0.0.1:8767. Mitään osoitetta ei tarvitse antaa käynnistyksessä: apupodin image ja projekti annetaan vasta vaiheessa 6.

6. Vie malli OpenShift AI:hin

  1. Perusta ensin OpenShift AI -projekti, johon haluat julkaista mallit: OpenShift AI → Projects → Create project (esim. llm-demo). Voit myös antaa uuden projektin nimen alla ja rastittaa Luo projekti, jos sitä ei ole; sovellus luo silloin projektin OpenShift AI:n tunnistamana. Käytä samaa projektia vaiheissa 6–8.
  2. Tässä välilehdessä: liitä Copy login command ja paina Kirjaudu.
  3. Valitse malli, projekti (se, jonka perustit), PVC:n nimi ja koko. PVC:n nimeksi ehdotetaan <malli>-pvc (oma PVC per malli).
  4. Täytä Apupodin image -kenttä (ks. alla).
  5. Paina Kopioi malli PVC:lle ja seuraa etenemistä.

Apupodin image: kopioinnin ajaksi klusteriin käynnistyy pieni apupodi (UBI9-image, jossa on tar). Air-gapped-klusteri ei pääse internetiin, joten kentässä pitää olla image, jonka klusteri voi hakea omasta rekisteristään. Kirjoita kenttään jokin näistä:

  • Klusterin sisäinen rekisteri: image-registry.openshift-image-registry.svc:5000/<projekti>/ubi9:latest, missä <projekti> on sama projekti kuin yllä olevassa Projekti-kentässä. Edellyttää, että UBI9 on tuotu sinne.
  • Yrityksen peilirekisteri: esim. quay.mycorp.local/mirror/ubi9/ubi:latest (kysy osoite ylläpidolta).
  • Klusteri pääsee internetiin: jätä oletus registry.access.redhat.com/ubi9/ubi:latest.

Jos sopivaa imagea ei ole klusterissa, tuo se ensin: katso (i)-ohjeen kohta Loader-image.

7. Deploy Model OpenShift AI:ssa

Tee deployment OpenShift AI:n konsolissa sovelluksen näyttämien ohjeiden mukaan: Models → Deploy model, Cluster storage (PVC) ja runtime (vLLM tai OpenVINO Model Server).

8. Testaa malli: notebook OpenShift AI:n workbenchissa

Kun malli on tilassa Started, voit testata sen notebookilla (OVMS/ONNX, vLLM-chat, embeddings). Tee testi samassa OpenShift AI -projektissa, jonka perustit kohdassa 6 (workbench ja deployment samassa projektissa).

Lataa osai_model_test.ipynb

  1. Tallenna tiedosto koneellesi (nappi yllä).
  2. OpenShift AI → Projects → oma projekti → Workbenches → Create workbench (esim. image Minimal Python / Jupyter). Odota tilaa Running ja avaa Open.
  3. JupyterLabissa: vasemman reunan tiedostoselaimessa Upload (nuoli ylös) → valitse osai_model_test.ipynb → avaa tuplaklikkaamalla.
  4. Kopioi mallin osoite: Models (Deployments) → malli → Inference endpoint (external, ilman polkua lopussa). Jos kyse on klusterin sisäisestä osoitteesta, workbench voi käyttää sitäkin.
  5. Notebookin osio 1. Asetukset: aseta ENDPOINT ja MODEL_NAME. MODEL_NAME on deploymentin nimi pienillä kirjaimilla ja ilman pistettä (esim. Qwen2-0.5B-Instruct → qwen2-05b-instruct, bge-small-en-v1.5 → bge-small-en-v15); Deploy-vaiheen tulosruutu ehdottaa oikean nimen. Token kysytään ajettaessa (OpenShift AI → deployment → Token authentication); jos autentikointi ei ole päällä, paina Enter.
  6. Aja ensin osio 2 (diagnostiikka): se tunnistaa runtimen (ovms/vllm). Sen jälkeen aja mallityyppiin sopiva osio: 3 ONNX/OpenVINO, 4 LLM (vLLM), 5 embedding.

Nimeämisohjeet: malli-id, deploymentin nimi ja PVC:n nimi noudattavat Kubernetes-nimeämistä (pienet kirjaimet, numerot ja viivat). Tarkemmat ohjeet ja esimerkit: vaiheen 7 tulosruudun kohta Model deployment name sekä notebookin osio 1. Jos kutsu antaa 404 (vLLM) tai tuntemattoman mallin (OVMS), tarkista ensin nimi: notebookin osio 2 listaa palvelimen käyttämän nimen.

Air-gapped: osio 3c hakee tietoja Hugging Facesta (HF_REPO = None ohittaa sen) ja ensimmäinen solu tekee %pip install, joten tarvittavat paketit (requests numpy pillow) pitää olla workbenchin imagessa tai omassa PyPI-peilissä. Embedding ovms_v2 tarvitsee lisäksi transformers ja tokenizerin (EMBED_HF_REPO).
